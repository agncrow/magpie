Magpie's parts at work

Each file of the package is a part a program may import on its own — use magpie.lz77, use magpie.fileformat — and call qualified (lz77.compress[…]): the codec, the bit packing, a column chunk, a bloom filter, the stemmer, a text column's postings, the file itself, the manifest, the merge, the executor, the nearest rows, the search, the Kafka wire's bytes and the sequencer. Each block below is a program that depends on the package, with what it prints; example.co runs every one in both modes. The functions are listed in REFERENCE.md; the log they make up is the tour in the Magpie book.

Magpie's codec, in Crow

Magpie's kernels were rewritten in Crow (docs/magpie-in-crow.md), the codec first: use magpie.lz77 brings compress and decompress, an LZ77 byte codec of our own over the sys layer's bytes, written with the bytes a kernel builds in place — bytes[n], set, push and concat where the bytes lie. A stream that is cut short, or decodes to another count than promised, is an error value saying why. The part's tests hold it to the streams the Rust kernel wrote, byte for byte, recorded before the kernel was deleted.

Bits and varints, in Crow


use magpie.bitpack is the second kernel ported: values packed at a
width of bits each, little-endian within and across bytes, and LEB128
varints for counts — what a Magpie file writes its columns and its
footer with. A value is a 64-bit pattern held as an int, so one at or

A column chunk, in Crow


use magpie.columnchunk is the third kernel ported: the cells of one column
over one row group as a Magpie file writes them — ints by frame of
reference or delta, floats as their bits, text plain or as a dictionary,
bools as a bitmap, moments, vectors — through the codec where it
shrinks them, the kernel's bytes byte for byte. chunk writes one,
unchunk reads it back as a column with its missing cells marked, and a
chunk cut short or of another kind is an error value saying why.
